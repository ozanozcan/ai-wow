# docs — one shape for everything a person reads

Every document in these repos is written to one standard so that a reader arriving
cold knows where they are, what they're looking at, and how to get to the part they
need in one click.

**The three rules. Nothing ships without all three.**

| # | Rule | Why |
|---|---|---|
| 1 | **A table of contents, at the top, every entry a working link** | The reader lands mid-scroll from a chat message. The TOC is how they orient and jump. |
| 2 | **Markdown in the repo is the source; a published page is a view of it** | Pages get stale and can't be diffed, grepped, or reviewed. The `.md` is what's true. |
| 3 | **Every claim traceable** — a file path, a decision id, a console you can open | A doc that can't be checked gets treated as a guess within a month. |

| Invocation | Mode | When |
|---|---|---|
| `/docs <subject>` | **write** | New document, or a rewrite of one. |
| `/docs audit [path]` | **audit** | Check a file, a directory, or the whole repo against this standard. Read-only, reports a list. |
| `/docs publish <path>` | **publish** | Render an existing `.md` into a self-contained HTML page (Artifact) using the house template. |

**Parse:** first word `audit` → audit; first word `publish` → publish; anything else → write.

Companion files, read the one you need:

- [`HOUSE-STYLE.md`](HOUSE-STYLE.md) — structure, voice, and the tells that make a document read as machine-written. **Read this before writing a single line of prose.**
- [`DIAGRAMS.md`](DIAGRAMS.md) — the SVG figure contract. What earns a diagram and what the class tokens mean.
- [`templates/doc.template.md`](templates/doc.template.md) — the markdown skeleton. Copy it.
- [`templates/page.template.html`](templates/page.template.html) — the published-page house style. Copy it; don't reinvent the CSS.
- [`scripts/check_toc.py`](scripts/check_toc.py) — proves every TOC link lands on a real heading. Zero dependencies.
- [`scripts/toc.py`](scripts/toc.py) — generates or refreshes a Contents block, keeping the glosses you wrote.

## The table of contents contract

This is the rule that gets skipped, so it is specified rather than described.

**Required in:** every document with **two or more `##` sections**. That is nearly all of
them — onboarding guides, wikis, runbooks, READMEs, plan and brainstorm write-ups,
research notes, published pages. A document with one section has nothing to table;
it does not get a stub TOC.

**Not in:** anything that fits on one screen — under 40 lines, or under 120 for a
`SKILL.md`, which an agent reads whole anyway. Nor in generated files, nor in a
skill's `reference/` tree, which is agent context rather than a document a person
opens. Add `<!-- docs:no-toc -->` to opt a file out deliberately.

### In markdown

Directly after the opening summary, before the first `---`, under a `## Contents`
heading. One line per `##`: a link, plus a short gloss wherever the heading doesn't
already say what the reader will find. The gloss is what turns an outline into a map,
so write one for every entry point document. Don't invent one to fill the pattern —
a heading that already carries its meaning stands alone.

```markdown
## Contents

- [How it reaches the tools](#how-it-reaches-the-tools) — the sync architecture
- [What lives here](#what-lives-here) — the map
- [The work loop](#the-work-loop) — idea → board → orchestrated build
```

Add `###` entries, indented one level, only when a `##` runs past roughly two screens.

**Anchor slugs** are generated by GitHub's rules, and getting them wrong is the one
way a TOC breaks silently:

| Heading | Anchor |
|---|---|
| `## What lives here` | `#what-lives-here` |
| `## What's in the box` | `#whats-in-the-box` — apostrophes are **dropped**, not replaced |
| `## Gate 1 — the bill` | `#gate-1--the-bill` — the em dash becomes nothing, but the spaces around it each become a hyphen |
| `## `ai-sync` status` | `#ai-sync-status` — backticks dropped |
| Two headings named `## Notes` | `#notes` and `#notes-1` |

Rule of thumb: lowercase, strip everything that isn't a letter, number, space, or
hyphen, then spaces → hyphens. **Then run the checker** — never hand-verify:

```bash
python3 skills/docs/scripts/check_toc.py docs/
```

### In a published page

The template does this; use it rather than rebuilding it.

- A persistent, visible-while-reading table of contents — not a list at the top that
  scrolls away.
- Click → jump. Every section needs an `id`, and every anchor target needs
  `scroll-margin-top` so the heading doesn't land under sticky chrome.
- The current section is marked as you scroll (`IntersectionObserver`, no libraries),
  and carries `aria-current`.
- Reachable at 390px without covering the document.
- `<nav aria-label="Contents">`, a skip link, visible `:focus-visible` rings.

## Mode: write

### 1. Establish who is reading and what they do next

Before structure, answer in one line each: **who opens this**, **what they are trying
to do**, **what they do immediately after reading**. If the answer to the third is
"nothing", the document is a reference — say so at the top and optimise for lookup,
not for reading order.

Two audiences, two documents, same facts — the split already in use in
`docs/onboarding/`: `<subject>.human.md` carries rationale and tradeoffs;
`<subject>.agent.md` is imperative with explicit VERIFY / STOP / DECISION markers.
Write both when an agent will execute the thing. Never let them disagree.

### 2. Ground it before writing it

Read the code, the board, and the existing docs the subject touches. A doc that
restates the plan without checking the repo is where drift starts. Anything you could
not verify goes in the sources footer as unverified, or gets cut.

### 3. Structure

Copy [`templates/doc.template.md`](templates/doc.template.md). The skeleton:

```
# Title — what this is in five words

**What it is / What it isn't / Why it exists** — three short paragraphs, no heading.
Links to the sibling doc and to the deeper source.

## Contents          ← the map, per the contract above

---

## <Sections>        ← ordered by the reader's path, not by system architecture
                       Each opens with the claim, then the evidence.

## Sources           ← files, decision ids, consoles. Where each fact came from.
```

Order sections by **dependency for the reader**: what they must understand or do
first comes first. Never number section headings — the TOC gives position, and
numbers rot the moment a section is inserted.

### 4. Write it

[`HOUSE-STYLE.md`](HOUSE-STYLE.md) is the authority. The short version:

- Lead with the claim. The first sentence of a section says the thing; the rest of
  the section is why it's true.
- Prefer a table when there are three or more parallel things with the same
  attributes. Prefer prose when there is an argument.
- Concrete over general — a path, a command, a number, a name.
- Say what breaks. A document with no failure modes in it was not written by someone
  who has done the thing.
- Cut every sentence that only announces what the next sentence says.

### 5. Figures

A diagram earns its place when it shows something prose is bad at: a topology, a flow
with branches, a comparison across two axes. Not when it re-lists what a table already
says. [`DIAGRAMS.md`](DIAGRAMS.md) has the contract, the class tokens, and the
accessibility requirements.

### 6. Verify before you call it done

```bash
python3 skills/docs/scripts/check_toc.py <path>
```

Then, by hand:

- [ ] Every internal link opens the right file — relative paths, not absolute.
- [ ] Every code block is runnable as written, or is marked as an excerpt.
- [ ] Sources footer names where each non-obvious fact came from.
- [ ] No secret, token, connection string, or personal address anywhere in the file.
- [ ] The document reads as though a person who has done this wrote it — run the
      tells list at the end of [`HOUSE-STYLE.md`](HOUSE-STYLE.md) over it.
- [ ] If the doc belongs to a directory with an `INDEX.md`, add its row.

## Mode: audit

Read-only. Report, don't rewrite, unless asked.

1. `python3 skills/docs/scripts/check_toc.py <path>` — broken and missing TOCs.
2. For each file flagged, note which of the three rules it fails.
3. Report as a table: file · what's missing · roughly how big a fix.
4. Offer to fix, in dependency order (INDEX files first — they're the entry points).

## Mode: publish

A published page is a **view**. It never contains a fact that isn't in the `.md`.

1. Confirm the source `.md` passes `audit`. Fix it there first — never patch the page
   and leave the source wrong.
2. Copy [`templates/page.template.html`](templates/page.template.html). Keep its CSS
   whole; keep the SVG class tokens intact.
3. Fill it. Sections in the same order as the source, with the same ids as the
   markdown anchors so links from chat land in the same place in both.
4. Self-contained only — inline CSS and JS, no CDN, no external fonts, no remote
   images. A strict CSP blocks every one of those.
5. Light and dark, via `prefers-color-scheme` **and** `:root[data-theme="…"]`.
6. Check it yourself at 1280px and 390px, both themes, before handing over the link.
7. Add a line to the source `.md` noting a rendered view exists and that the `.md`
   remains the source — the pattern already in `docs/onboarding/INDEX.md`.

Republishing an existing page: pass its URL so it updates in place instead of minting
a second link that will drift from the first.
